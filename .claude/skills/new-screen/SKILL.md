# New screen / route

Routes live in `src/app/` (Expo Router, file-based). Route files are **thin**: they only re-export a screen from a feature and set navigator options.

## Choose the route type

| Need          | File                                                                                                                                  |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| New tab       | `src/app/(tabs)/<name>.tsx` + add `<Tabs.Screen name="<name>" …>` with title (i18n) and Ionicons icon in `src/app/(tabs)/_layout.tsx` |
| Pushed screen | `src/app/<name>.tsx` (root Stack) or inside a group with its own `_layout.tsx`                                                        |
| Dynamic       | `src/app/<thing>/[id].tsx` → `useLocalSearchParams<{ id: string }>()` and validate with zod                                           |
| Modal         | `src/app/<name>.tsx` + in `src/app/_layout.tsx` declare `<Stack.Screen name="<name>" options={{ presentation: 'modal' }} />`          |

## Steps

1. Create the screen component in the feature: `src/features/<feature>/components/<name>-screen.tsx`, wrapped in `<Screen>` from `@/components/ui`. Export it from the feature's `index.ts`.
2. Create the route file:
   ```tsx
   import { ThingScreen } from '@/features/thing';

   export default ThingScreen;
   ```
   For screen options use `<Stack.Screen options={{ title: t('…') }} />` inside the screen, or in the layout.
3. Link to it with `<Link href="/path" asChild><Button … /></Link>` (gives real `<a>` on web) or `router.push('/path')`.
4. Add i18n keys (en + nl) for titles/labels.
5. Web: every route is statically rendered at build time — don't access `window`/storage during render.
6. Add a Playwright check that the route renders and is reachable via navigation, and run `pnpm screenshot /path`.

## Notes

- Import `Tabs` from `expo-router/js-tabs` (the root export is deprecated).
- Typed routes are enabled (`experiments.typedRoutes`): `.expo/types` is generated by `pnpm start`; `href` strings are checked when present.
- Deep links use scheme `clapp://` (see `app.json`).
